# Proposal

## Why

In `.github/scripts/clean-release-changelog.test.mjs`, the unit test `checkReleaseRange skips check when base version equals current version` tests the skipping behavior of `checkReleaseRange` when `baseVersion === currentVersion`. However, the test passed `rootDir: process.cwd()` and mocked `execGit` with hardcoded `"0.20.0\n"` for `origin/main:version.txt`. On automated release pull requests generated by Release Please (such as PR #537), `version.txt` in the working tree is bumped to the upcoming release version (e.g. `0.21.0`), causing `baseVersion !== currentVersion`. As a result, the test failed to skip, attempted to validate `CHANGELOG.md`'s release section by invoking `git log -1` through `execGit`, and threw an unhandled `Unexpected git invocation` exception.

This failure breaks the required `design-pattern-governance` CI job (`node --test .github/scripts/*.test.mjs`) on release pull requests where `version.txt` is bumped, blocking releases from passing checks and shipping.

## What Changes

- Isolate `checkReleaseRange skips check when base version equals current version` in `.github/scripts/clean-release-changelog.test.mjs` using an ephemeral temporary directory created with `mkdtempSync` and cleaned up with `rmSync` in a `finally` block.
- Write an isolated `version.txt` matching the mocked base version within the temporary directory, ensuring the test is strictly self-contained and completely independent of ambient working tree state or the root `version.txt`.
- Remove the redundant and unasserted first call to `checkReleaseRange` in that test.
