## Why

1. SonarQube analysis currently waits on the longest verification checks in the repository via `needs: [ci, sdk, contract, coverage]`, forcing it to wait ~7–8 minutes for the full SDK validate suite and contract audit to complete before initiating its scan. However, Sonar only consumes the LCOV artifact generated by `coverage` and source files. Because `coverage` already builds the TypeScript SDK and executes its runtime tests, Sonar can safely run in parallel with the SDK and contract jobs immediately after `coverage` completes, removing approximately 80–100 seconds from the normal critical-path duration.
2. Three required contexts (`ci / audit`, `sdk`, and `contract`) share an unretried `npm audit` call. An audit endpoint outage or transient latency blip causes npm to hang for up to five minutes before failing with a transport error, blocking merges across the repository despite zero vulnerabilities (#286). A bounded, transport-only retry mechanism with fast timeouts mitigates endpoint instability without weakening vulnerability detection.

## What Changes

- Decouple `sonar` in `.github/workflows/ci.yml` from `ci`, `sdk`, and `contract`, depending solely on `coverage`.
- Implement `.github/scripts/npm-audit-retry.mjs` to invoke `npm audit` with an explicit 30s timeout (`--fetch-timeout=30000`) and up to two retries strictly triggered on transport-level network errors.
- Enforce the null control: ensure genuine advisories at or above the audit level exit immediately with failure without retrying into an accidental pass.
- Update `sdk` and `contract` jobs in `.github/workflows/ci.yml` to use `.github/scripts/npm-audit-retry.mjs`.
- Add unit tests in `.github/scripts/npm-audit-retry.test.mjs` verifying classification of transport failures vs advisories and bounded retry behavior.
