# Bloodtrail

Personal open-source project by Fernando Homem da Costa (`nandohdc`). A contract-bound security audit event system: a canonical event contract plus a framework-independent TypeScript SDK that emits events conforming to it.

There is **no root `package.json`** — every workspace is standalone. Always run npm scripts with `--prefix` or from inside the package directory.

## Layout

| Path | What it is |
|---|---|
| `contracts/security-audit/` | The canonical contract. `source/contract.source.json` is the **single source of truth**; `catalog/`, `registries/`, `policies/`, `docs/`, `adr/` are **generated — never hand-edit**. |
| `packages/security-audit-sdk-core/` | `@bloodtrail/security-audit-sdk-core` — ESM TypeScript SDK core. Private, unpublished, unlicensed for distribution. |
| `openspec/` | Spec-driven change management. `specs/` holds current capability specs; `changes/` holds in-flight change proposals; `changes/archive/` holds completed ones. |
| `research/` | Isolated investigations (e.g. `browser-telemetry`). Research artifacts, not shipping code. |

Canonical boundary: **Bloodtrail is canonical.** OCSF 1.8.0 is export-only. OpenTelemetry 1.59.0 / Semantic Conventions 1.43.0 are transport-only. CloudEvents 1.0.2 is optional envelope-only.

## Authorization boundary

The SDK is an **isolated technical candidate**. Its existence does not authorize production deployment, real-user data processing, framework instrumentation, production transports/exporters/collectors/storage/SIEM integration, analytics, detection, browser telemetry, or cryptographic audit-log chaining. Only a transport-neutral sink interface and non-production test sinks exist. Do not propose or add any of the above as an incidental part of another change.

## Workflow — openspec, spec-driven

Changes go through openspec. Use the `openspec-*` skills rather than editing change directories by hand:

- `openspec-propose` / `openspec-new-change` — start a change (proposal, specs delta, design, tasks)
- `openspec-continue-change` / `openspec-update-change` / `openspec-apply-change` — work it
- `openspec-verify-change` — check it before commit
- `openspec-archive-change` / `openspec-sync-specs` — land it and fold deltas into `specs/`
- `openspec-explore` / `openspec-onboard` — orient in the repo

Specs under `openspec/specs/<capability>/spec.md` describe what the system must do. A change's `specs/` entries are **deltas**, not replacements.

Those skills are generated into `.hermes/skills/` by the `openspec` CLI (`openspec update`), but **Hermes does not discover them automatically** — it scans only the active profile's skills directory plus the dirs named in `skills.external_dirs`. Without that key the skills fail as `Skill '<name>' not found`. Register this repo's copy once, in the profile's `config.yaml`:

```yaml
skills:
  external_dirs:
    - /path/to/bloodtrail/.hermes/skills
```

Register `.hermes/skills` only. `.claude/skills/` and `.agents/skills/` are the same 12 skills rebodied for other tools; adding a second copy makes every `openspec-*` name ambiguous and Hermes refuses to load rather than guessing.

## Validation gates

Node engine is pinned: `>=24 <25 || >=26 <27`.

```bash
# SDK — full chain (19 gates: generate, typecheck, build, runtime, types,
# examples, exports, compatibility, contract-immutability, scope, publication-path,
# dependencies, package, changed-paths, governance-history, archive-attestations,
# coherence, verification, git)
npm run validate --prefix packages/security-audit-sdk-core

# SDK — build + cross-cutting matrix, no git/package/coherence gates
npm run test:matrix --prefix packages/security-audit-sdk-core

# Contract — regenerate check + contract tests
npm run validate --prefix contracts/security-audit
```

Targeted gates worth knowing (all `--prefix packages/security-audit-sdk-core`):

- `check:generated` — `src/generated/` matches the contract; regenerate with `npm run generate`
- `test:contract-immutability` — the frozen contract was not mutated
- `test:compatibility` — `compatibility.json` still holds
- `test:scope` — no out-of-scope surface crept in (enforces the authorization boundary above, forbidden filenames, imports, exports, and undeclared platform coupling)
- `test:publication-path` — nothing in tracked content can publish the package: no manifest script,
  automation file, workflow-referenced local action, `.npmrc`, `publishConfig`, or non-private manifest
- `test:governance-history` — declared merge parentage, bound-commit reachability, governed-commit
  resolution, and exact reviewed-path-to-content-object binding
- `test:archive-attestations` — every declared archive-movement attestation and its archive match the
  commit history shows introduced it
- `test:verification` — `tests/verification/*.test.mjs`, the mutation/evidence suite
- `test:changed-paths` / `test:git` — staged scope and git state are clean

Generated code (`src/generated/contract.generated.ts`) is derived from the contract — change the contract source and regenerate, never edit the output.

## Commit conventions

- **Staged, evidence-backed changes.** Run read-only semantic verification *before* committing; do not regenerate, reformat, or rerun tests on a candidate that has already been verified.
- **Separate commits** for proposal, implementation, and archive. Do not mix them.
- **Stage an explicit allowlist only.** Leave unrelated untracked files untouched; verify local/remote commit identity and report exact scope.
- **Batch routine documentation updates.** `AGENTS.md`, `CLAUDE.md`, `.hermes.md`, and `CONTRIBUTING.md` are `governance_core` paths. Modifying them triggers `governance_core_path` and forces a full OpenSpec assessment with 15-dimension security justifications. Never touch them incidentally alongside an unrelated bounded change. Defer routine documentation edits to dedicated batched documentation changes.
- **AI review is not approval.** Never treat an AI review, a PR assignment, or an informal message as human or organizational approval. Bind formal reviews to the exact reviewed commit hash.
- Conventional-commit prefixes are in use: `feat(...)`, `fix(...)`, `docs(openspec): ...`, `revert: ...`.
