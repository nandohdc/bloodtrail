## Proven findings

### F1 — The package's content is a projection of #86's SPI list, and nothing else

Five platform capabilities plus one context provider. If a sixth thing appears in this package, either
#86's SPI list was incomplete or this package is growing scope. Both are worth stopping for.

### F2 — The shutdown contract is already written and must be reproduced exactly

`shutdownTimerOwnership` fixes: `unref` on the handle; idempotent clear in a structured `finally` after
either race outcome; logical timeout preserved while the process is active; **no idle-process retention**;
no signal handlers installed; no intervals installed. That is a complete specification of the timer
binding. Copy it; do not re-derive it.

The clause "no signal handlers installed" is the one a well-meaning Node binding will violate — a binding
that wires `SIGTERM` to `shutdown()` looks helpful and breaks the contract. #87's own out-of-scope line
says process signal wiring for every deployment platform is excluded.

### F3 — The generated CJS validator lands here, and it drags two gates with it

`schema-validator.generated.cjs` is generated by the contract pipeline into the SDK package and copied to
`dist/` by `copy-generated-validator.mjs`. If it moves to the Node binding, then: `check:generated`'s
byte-comparison target moves, `copy-generated-validator.mjs` moves, `modulePolicy` in `compatibility.json`
moves, and `check-package-contents.mjs` must prove the binding's tarball imports. **The fix is in the
generator, never in its output** — so the generator's output path is what changes.

### F4 — Zero runtime dependencies applies to this package too

`dependencies`, `peerDependencies` and `optionalDependencies` must stay empty, and `check-scope.mjs`'s
manifest rules enforce it for the SDK. Whatever gate #88 produces must enforce the same for the binding.
The Node binding uses only `node:*` built-ins, which are not dependencies.

### F5 — "Reproduces existing Node behaviour" is a differential, and the baseline must be captured first

Before the split, capture the full `validate` output, the runtime test results, the scope inventory and
the example run. After the split, the binding plus Core must reproduce all of it. **Capture before, not
after** — this is the same discipline as #83's Task 1.

### F6 — Provisional means the API surface is explicitly unfrozen

#87's out-of-scope line excludes freeze. Say so in the package's own README and in `compatibility.json`:
this surface may change without a major until #111 records the freeze against #109's evidence.

### F7 — `area:server` is a label, not a licence

The binding is a platform adapter, not a transport. No HTTP, no collector, no framework integration. The
authorization boundary applies unchanged, and `check-scope.mjs`'s forbidden filename and export terms must
apply to this package too — which is #88's job.

## Risks and open questions

- **Signal handlers (F2)** are the most likely accidental contract violation.
- **The validator move (F3) touches the generation pipeline**, which is the part of this repository where
  a mistake is hardest to see. `check:generated` before `validate`, always.
- **A leak that only appears under load** will not show in a unit test. Child-process tests that assert
  process exit are the honest instrument.
- **Open question:** does the clock stay in Core (`new Date()` couples to nothing) or move to the binding?
  Moving it is more uniform; keeping it is less code. #86's SPI list decides — do not decide it here.

## What this does not authorize

Freezing the API, transport, collector, framework adapters, production instrumentation, publication, or
any non-Node binding.

## What this plan did not verify

Whether the generated CJS validator can be wrapped behind an SPI without leaking Ajv's shape into the
public surface. That is #86's hardest question and it lands here.
